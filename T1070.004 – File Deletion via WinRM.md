# T1070.004 – File Deletion via WinRM

## Overview

File Deletion (T1070.004) is a defense evasion technique in which attackers delete files from a compromised system to remove artifacts, tools, payloads, or other evidence of their activity.

This detection demonstrates how suspicious file deletion can be identified using Sysmon endpoint telemetry and validated within Microsoft Sentinel.

The simulation uses PowerShell Remoting to execute a file deletion operation on the Windows victim endpoint. Sysmon Event ID 23 records the deletion, while `wsmprovhost.exe` identifies the Windows Remote Management execution context.

## Detection Objective

The objective of this detection is to identify deletion of a designated file when the deletion occurs through a PowerShell Remoting / WinRM execution context.

The detection monitors:

```text
Sysmon Event ID 23
+
wsmprovhost.exe
+
C:\T1070.004_Test.txt
```

The specific file used during the lab simulation was:
```
C:\T1070.004_Test.txt
```
The detection is intentionally specific to the lab artifact so that the simulated activity can be validated without generating unnecessary noise from normal file 
deletion activity.

---

### Attack Simulation

The attacker VM remotely executed a PowerShell deletion command against the victim VM using PowerShell Remoting.

The command executed was:
```Powershell
Invoke-Command -ComputerName 10.0.1.4 -Credential $cred -ScriptBlock {
    Remove-Item -LiteralPath "C:\T1070.004_Test.txt" -Force
}
```
The command completed without returning an error.

The deletion was therefore performed remotely on:
```
SC200-Victim01
```
through the Windows Remote Management execution context.

### Detection Query

```KQL
Event
| where Computer == "SC200-Victim01"
| where EventID == 23
| where TimeGenerated > ago(5m)
| extend ParsedXML = parse_xml(EventData)
| mv-expand Data = ParsedXML.DataItem.EventData.Data
| extend
    FieldName = tostring(Data["@Name"]),
    FieldValue = tostring(Data["#text"])
| summarize
    Fields = make_bag(pack(FieldName, FieldValue))
    by TimeGenerated, EventID
| project
    TimeGenerated,
    EventID,
    ProcessGuid = tostring(Fields.ProcessGuid),
    ProcessId = tostring(Fields.ProcessId),
    User = tostring(Fields.User),
    Image = tostring(Fields.Image),
    TargetFilename = tostring(Fields.TargetFilename),
    Hashes = tostring(Fields.Hashes)
| where Image endswith @"\wsmprovhost.exe"
| where TargetFilename == @"C:\T1070.004_Test.txt"
```

---

### Detection Logic

The query performs the following operations.

1. Filter the Victim Endpoint
```KQL
| where Computer == "SC200-Victim01"
```
This restricts the detection to the Windows victim used in the lab.

2. Search for File Deletion
```
| where EventID == 23
```
Sysmon Event ID 23 represents a file deletion event.
This is the primary telemetry used by the detection.

3. Parse Sysmon XML
```
| extend ParsedXML = parse_xml(EventData)
```
The Sysmon fields are contained inside the EventData XML structure.
The query parses this XML and expands the individual data fields.

4. Extract Relevant Fields

The query extracts the field name and associated value:
```
FieldName = tostring(Data["@Name"]),
FieldValue = tostring(Data["#text"])
```
The fields are then reconstructed into a field bag:
```
Fields = make_bag(pack(FieldName, FieldValue))
```
This allows the detection to reference:
```
ProcessGuid
ProcessId
User
Image
TargetFilename
Hashes
```
5. Identify the WinRM Execution Context

The query filters on:
```
| where Image endswith @"\wsmprovhost.exe"
```
This identifies file deletion events associated with:
```
wsmprovhost.exe
```
During the simulation, the relevant image was:
```
C:\Windows\System32\wsmprovhost.exe
```
This provides additional context that the deletion occurred through the Windows Remote Management execution infrastructure.

6. Identify the Deleted File

The final condition is:
```
| where TargetFilename == @"C:\T1070.004_Test.txt"
```
This restricts the detection to the specific file used during the lab simulation.

The resulting detection logic is therefore:
```
Sysmon Event ID 23
        +
wsmprovhost.exe
        +
C:\T1070.004_Test.txt
```

---

### Why wsmprovhost.exe?

PowerShell Remoting uses the Windows Remote Management execution infrastructure.

During the simulation, the deletion command was executed remotely against the victim endpoint.

The associated process image was:
```
C:\Windows\System32\wsmprovhost.exe
```
Using wsmprovhost.exe as an execution-context indicator allows the detection to distinguish the simulated remote deletion activity from a generic file deletion event.

This is important because legitimate applications and users can also delete files.

The detection therefore does not claim that every file deletion by wsmprovhost.exe is malicious.

Instead, it combines the execution context with the specific deleted file to identify the simulated T1070.004 behaviour.

### Investigation Fields

When the detection triggers, an analyst should review:


| **Field**        | **Purpose**                                               |
| ---------------- | --------------------------------------------------------- |
| `TimeGenerated`  | Establish the time of the deletion                        |
| `Computer`       | Identify the affected endpoint                            |
| `User`           | Identify the account associated with the deletion         |
| `Image`          | Identify the process associated with the deletion         |
| `TargetFilename` | Identify the file that was deleted                        |
| `ProcessGuid`    | Correlate the process with other Sysmon events            |
| `ProcessId`      | Identify the process involved at the time of the event    |
| `Hashes`         | Provide hash information associated with the deleted file |

The TargetFilename is particularly useful because it allows the analyst to determine what artifact was removed.

ProcessGuid can also be useful when correlating the deletion with other Sysmon events generated by the same process.

### False Positive Considerations

File deletion is common during normal Windows and administrative activity.

Potential legitimate sources include:

Temporary file cleanup
Software uninstallers
Application updates
Administrative scripts
Configuration management
Scheduled maintenance
User activity

wsmprovhost.exe can also be associated with legitimate PowerShell Remoting.
Therefore, this detection should not automatically treat every matching event as malicious.

Production implementations should consider additional context such as:

Source host
User account
Deleted file path
File type
Process command line
Parent process
Previous file creation
File hash
Network activity
Whether the remote administrative activity was expected
Detection Limitations

This lab detection intentionally focuses on a narrow behavioral signal.

The query identifies:
```
File Deletion
+
wsmprovhost.exe
+
Specific Target File
```
This does not independently prove malicious intent.

The use of a specific filename makes the lab detection highly precise but limits its ability to detect arbitrary file deletion activity.

A broader production detection could monitor suspicious file deletion activity without restricting the filename:
```
Sysmon Event ID 23
+
Suspicious Execution Context
+
Suspicious File Location
```
The detection could also be strengthened by correlating the deletion with earlier file creation and process execution telemetry.

For example:
```
File Creation
        ↓
Process Execution
        ↓
Remote Execution
        ↓
File Deletion
```
This could provide stronger evidence of an attacker staging an artifact and subsequently removing it.

### Key Learning

The important lesson from this detection is that file deletion can be a meaningful defense-evasion signal when it is placed in the correct execution context.

In this lab, the useful behavioral signal was:
```
Sysmon Event ID 23
        +
wsmprovhost.exe
        +
C:\T1070.004_Test.txt
```
Sysmon provided visibility into the deletion, while Microsoft Sentinel provided the detection and alerting layer.

The TargetFilename field identifies the artifact that was removed, while Image, User, ProcessGuid, and ProcessId provide additional investigation context.

In a production environment, the detection could be expanded beyond a single test filename and correlated with process creation, file creation, command-line, and 
network telemetry to identify more complete attacker cleanup behaviour.
