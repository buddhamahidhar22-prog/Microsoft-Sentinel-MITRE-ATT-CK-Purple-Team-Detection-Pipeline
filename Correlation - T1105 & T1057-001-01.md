# Correlation – T1105 & T1057-001-01

## Overview

This correlation detection identifies a sequence in which an attacker first transfers a tool or payload to a Windows endpoint and then performs process discovery activity.

Ingress Tool Transfer (T1105) can provide an attacker with additional tools or payloads required for subsequent activity. Process Discovery (T1057) can then be used to enumerate running processes on the compromised system and identify security software, applications, or other processes of interest.

Individually, these behaviours can occur legitimately. Correlating them within a short time window provides additional context and can increase confidence that the activity is associated with post-compromise attacker behaviour.

This detection demonstrates how multiple Sysmon events can be correlated within Microsoft Sentinel using KQL to identify a potential attacker workflow rather than relying solely on an individual event.

## Detection Objective

The objective of this detection is to identify a sequence in which:

1. A tool or file is transferred to the Windows endpoint.
2. Process discovery activity occurs shortly afterwards.

The correlation provides additional context around the individual detections and helps identify a potential post-compromise workflow.

The detection uses Sysmon telemetry ingested into Microsoft Sentinel and correlates events based on the endpoint and time of execution.

## Detection Query

```KQL

Event
| where Computer == "SC200-Victim01"
| where EventID == 11
| where TimeGenerated > ago(30m)
| extend ParsedXML = parse_xml(EventData)
| mv-expand Data = ParsedXML.DataItem.EventData.Data
| extend
    FieldName = tostring(Data["@Name"]),
    FieldValue = tostring(Data["#text"])
| summarize
    Fields = make_bag(pack(FieldName, FieldValue))
    by TimeGenerated, EventID, Computer
| project
    T1105Time = TimeGenerated,
    Computer,
    User = tostring(Fields.User),
    T1105Image = tostring(Fields.Image),
    TargetFilename = tostring(Fields.TargetFilename)
| where T1105Image endswith @"\wsmprovhost.exe"
| join kind=inner (
    Event
    | where Computer == "SC200-Victim01"
    | where EventID == 13
    | where TimeGenerated > ago(30m)
    | extend ParsedXML = parse_xml(EventData)
    | mv-expand Data = ParsedXML.DataItem.EventData.Data
    | extend
        FieldName = tostring(Data["@Name"]),
        FieldValue = tostring(Data["#text"])
    | summarize
        Fields = make_bag(pack(FieldName, FieldValue))
        by TimeGenerated, EventID, Computer
    | project
        T1547Time = TimeGenerated,
        Computer,
        User = tostring(Fields.User),
        T1547Image = tostring(Fields.Image),
        TargetObject = tostring(Fields.TargetObject),
        Details = tostring(Fields.Details)
    | where TargetObject has @"\Software\Microsoft\Windows\CurrentVersion\Run\"
) on Computer, User
| where T1547Time >= T1105Time
| where T1547Time <= T1105Time + 15m
| project
    T1105Time,
    T1547Time,
    Computer,
    User,
    T1105Image,
    TargetFilename,
    T1547Image,
    TargetObject,
    Details
| order by T1105Time desc
```

## Detection Logic

The detection is divided into two components.

Stage 1 – Ingress Tool Transfer
The first query identifies file creation activity associated with the arrival of a tool or payload on the endpoint.

The following fields are extracted:

User
Process Image
Target Filename
Timestamp

This represents the first stage of the potential attacker workflow.

Stage 2 – Process Discovery
The second query identifies process execution associated with process discovery.

The detection searches command-line activity for process enumeration utilities or commands such as:

tasklist
Get-Process
wmic

The following fields are extracted:

User
Process Image
Command Line
Parent Process
Timestamp
Correlation

The two event streams are then joined using the affected computer and a defined time window.

Conceptually:

T1105
Tool / File Transfer
        |
        | within defined time window
        v
T1057
Process Discovery
        |
        v
Correlated Detection

The correlation provides additional context that is not available when examining either event independently.

Detection Validation

The detection was validated by generating the individual behaviours and reviewing the resulting Sysmon telemetry within Microsoft Sentinel.

Validation confirmed:

Tool/file transfer telemetry was generated.
The transferred file was visible through Sysmon telemetry.
Process discovery activity generated process creation telemetry.
The relevant command-line information was captured.
Both activities were ingested into Microsoft Sentinel.
The two behaviours could be correlated using the endpoint and event timestamps.
The correlation query returned the expected activity.

## Outcome

This correlation detection demonstrated how multiple attacker behaviours can be combined to identify a potential post-compromise workflow.

The simulated activity followed the sequence:

Ingress Tool Transfer
        ↓
Tool / File appears on endpoint
        ↓
Process Discovery
        ↓
Enumeration of running processes
        ↓
KQL Correlation
        ↓
Microsoft Sentinel Analytics Rule
        ↓
Alert / Incident

Rather than relying on a single suspicious event, the detection combines two ATT&CK techniques and evaluates their temporal relationship.

This demonstrates how event correlation can improve detection confidence and provide additional context for security investigations.
Sysmon Event ID 11 provides visibility into files created on the endpoint following the transfer activity.

The combination of process and file telemetry provides the context required to correlate the two behaviours.
