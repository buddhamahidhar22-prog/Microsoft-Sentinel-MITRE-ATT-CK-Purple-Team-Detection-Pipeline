# T1574.001 – DLL Search Order Hijacking

## Overview

DLL Search Order Hijacking (T1574.001) is a technique where an attacker places a malicious DLL in a location that is searched before the legitimate DLL location. When a legitimate executable attempts to load the DLL, Windows may load the attacker-controlled DLL instead.

This detection demonstrates how suspicious DLL loading can be identified using Sysmon Image Load telemetry (Event ID 7) and validated within Microsoft Sentinel after simulating attacker behaviour with Atomic Red Team.

The detection focuses on identifying processes executing from non-standard or user-controlled locations that load DLLs from the same non-standard location instead of expected Windows system directories.

## Detection Objective

The objective of this detection is to identify suspicious DLL loading behavior on a Windows endpoint using Sysmon Image Load telemetry (Event ID 7).

The detection looks for a process executing from a non-standard location and loading a DLL from a non-standard or user-controlled directory.

Legitimate Windows processes commonly load DLLs from locations such as:

- `C:\Windows\System32\`
- `C:\Windows\SysWOW64\`
- `C:\Windows\Microsoft.NET\`
- `C:\Windows\assembly\`
- `C:\ProgramData\Microsoft\Windows Defender\`

A DLL loaded from a user-controlled directory such as:

`C:\Users\sc200admin\atomic\`

can therefore provide a useful behavioural indicator when combined with the executing process and other telemetry.

## KQL Detection Query:

```KQL
Event
| where EventID == 7
| extend ParsedXML = parse_xml(EventData)
| mv-expand Data = ParsedXML.DataItem.EventData.Data
| extend
    FieldName = tostring(Data["@Name"]),
    FieldValue = tostring(Data["#text"])
| summarize
    Fields = make_bag(pack(FieldName, FieldValue))
    by TimeGenerated, Computer, EventID
| project
    TimeGenerated,
    Computer,
    EventID,
    Image = tostring(Fields.Image),
    ImageLoaded = tostring(Fields.ImageLoaded),
    Hashes = tostring(Fields.Hashes),
    Signed = tostring(Fields.Signed),
    Signature = tostring(Fields.Signature),
    SignatureStatus = tostring(Fields.SignatureStatus),
    User = tostring(Fields.User)
| where Image endswith @"\ntprint.exe"
| where ImageLoaded endswith @"\ntprint.dll"
| where ImageLoaded !startswith @"C:\Windows\System32\"
```

## Detection Logic

The detection uses Sysmon Event ID 7 to identify DLL image loading activity.

Because the required Sysmon fields were contained within the XML EventData rather than being directly exposed as individual Sentinel columns, the XML was parsed using parse_xml() and the individual Data elements were expanded and converted into a dynamic field bag.

The query extracts:

Image – process responsible for loading the DLL
ImageLoaded – DLL or module loaded by the process
Hashes – hash information for the loaded image
Signed – signing status
Signature – publisher/signature information
SignatureStatus – signature validation status
User – account associated with the activity

The detection then focuses on DLLs loaded from locations outside expected Windows system directories.

This reduces the scope of the detection from the large volume of normal Event ID 7 telemetry to DLL loads occurring from potentially suspicious locations.

## Detection Validation

The detection was validated using telemetry generated by the Atomic Red Team T1574.001 simulation.
The generated Sysmon Event ID 7 telemetry showed a process executing from a user-controlled directory and loading a DLL from the same non-standard location.

``` Example:

Image:
C:\Users\sc200admin\atomic\ntprint.exe

ImageLoaded:
C:\Users\sc200admin\atomic\ntprint.dll
```

The DLL was therefore loaded from a location outside the expected Windows system directories.

Validation confirmed:

Sysmon Event ID 7 was generated.
The executing process was identified.
The loaded DLL was identified.
The DLL was loaded from a non-standard user-controlled path.
Hash information was available.
Digital signature information was available.
The activity was ingested into Microsoft Sentinel.
The KQL detection identified the suspicious DLL loading behaviour.

## Microsoft Sentinel Analytics Rule

After validating the KQL query against the generated Sysmon telemetry, the detection was implemented as a Microsoft Sentinel Analytics Rule.

The Analytics Rule was configured to monitor for suspicious DLL loading behaviour and generate an alert when the detection logic matched endpoint telemetry.

The rule was mapped to:

MITRE ATT&CK:
T1574.001 – DLL Search Order Hijacking

The generated alert was subsequently promoted into a Microsoft Sentinel incident, confirming that the detection could move beyond query-level validation into an operational SIEM detection workflow.

## Outcome

This detection successfully identified suspicious DLL loading behaviour generated by Atomic Red Team using Sysmon Image Load telemetry.
The simulation demonstrated a process executing from a non-standard user-controlled directory and loading a DLL from that same location. Sysmon Event ID 7 captured the image-loading relationship, while Microsoft Sentinel provided the telemetry analysis and detection layer.
A custom KQL query was developed to parse the Sysmon XML data, extract the relevant process and DLL information, filter expected system locations, and identify suspicious DLL loading behaviour.
The validated query was subsequently implemented as a Microsoft Sentinel Analytics Rule and successfully generated an alert and incident from the simulated activity.
