# T1547.001 – Registry Run Keys / Startup Folder

## Overview

Registry Run Keys / Startup Folder (T1547.001) is a Windows persistence technique in which an attacker modifies registry locations that are automatically processed during user logon or system startup.

By placing an executable or command in a Registry Run Key, an attacker can establish persistence so that the configured program is executed automatically when the affected user logs on.

This detection demonstrates how Registry Run Key modification can be identified using Sysmon registry telemetry and validated within Microsoft Sentinel after simulating attacker behaviour with Atomic Red Team.

## Detection Objective

The objective of this detection is to identify modifications to Windows Registry Run Keys that may establish persistence on the victim endpoint.

The simulation modifies the following registry location:

```text
HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
```

The modification generates Sysmon Event ID 13 – Registry Value Set telemetry, which is ingested into Microsoft Sentinel.

The detection focuses on registry modifications targeting the Windows CurrentVersion\Run registry location.

The registry modification was also validated through PowerShell Remoting from the attacker VM.

The following command was executed against the victim:
```Powershell
Invoke-Command -ComputerName 10.0.1.4 -Credential $cred -ScriptBlock {
    cmd.exe /c 'REG ADD "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" /V "Atomic Red Team" /T REG_SZ /F /D "C:\Path\AtomicRedTeam.exe"'
}
```

### Detection Query

The following KQL query searches Sysmon Event ID 13 telemetry for modifications to Windows Registry Run Keys.

```KQL
Event
| where Computer == "SC200-Victim01"
| where EventID == 13
| where TimeGenerated > ago(5m)
| extend ParsedXML = parse_xml(EventData)
| mv-expand Data = ParsedXML.DataItem.EventData.Data
| extend
    FieldName = tostring(Data["@Name"]),
    FieldValue = tostring(Data["#text"])
| summarize
    Fields = make_bag(pack(FieldName, FieldValue))
    by TimeGenerated, EventID
| project
    TimeGenerated,
    EventID,
    Image = tostring(Fields.Image),
    TargetObject = tostring(Fields.TargetObject),
    Details = tostring(Fields.Details),
    User = tostring(Fields.User)
| where TargetObject has @"\Software\Microsoft\Windows\CurrentVersion\Run\"
```

---

### Detection Logic

The query performs the following operations.

1. Filter the Victim Endpoint
| where Computer == "SC200-Victim01"

This restricts the detection to the Windows victim used in the lab.

2. Search for Registry Modification
| where EventID == 13

Sysmon Event ID 13 represents a registry value being set.

This is the primary telemetry used by the detection.

3. Parse Sysmon XML
| extend ParsedXML = parse_xml(EventData)

The Sysmon fields are contained inside the EventData XML structure.

The query parses this XML and expands the individual data fields.

4. Extract Relevant Fields

The query extracts the field name and associated value:

FieldName = tostring(Data["@Name"]),
FieldValue = tostring(Data["#text"])

The fields are then reconstructed into a field bag:

Fields = make_bag(pack(FieldName, FieldValue))

This allows the detection to reference:

Image
TargetObject
Details
User
5. Identify Registry Run Key Modification

The final detection condition is:

| where TargetObject has @"\Software\Microsoft\Windows\CurrentVersion\Run\"

This identifies registry modifications involving the Windows Registry Run Key location.

The detection therefore focuses on the persistence mechanism rather than a specific executable filename.

Why CurrentVersion\Run?

Windows Registry Run Keys can be used to configure applications that execute automatically during user logon.

The simulated activity modified:

HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run

The created value was:

Atomic Red Team

with the configured data:

C:\Path\AtomicRedTeam.exe

This provides a clear example of how an attacker could establish persistence through a Registry Run Key.

The detection does not assume that every Run Key modification is malicious.

Legitimate applications and administrative software may also create or modify Run Key entries.

The registry modification therefore represents a strong investigation signal that should be evaluated alongside the executable path, user, parent process, and surrounding activity.

Investigation Fields

When the detection triggers, an analyst should review:

Field	Purpose
TimeGenerated	Establish the time of the registry modification
Computer	Identify the affected endpoint
User	Identify the account responsible for the activity
Image	Identify the process that modified the registry
TargetObject	Identify the registry key and value modified
Details	Identify the data written to the registry value

The TargetObject and Details fields are particularly important.

For example:

TargetObject:
HKU\...\SOFTWARE\Microsoft\Windows\CurrentVersion\Run\Atomic Red Team

and:

Details:
C:\Path\AtomicRedTeam.exe

Together, these fields provide evidence of what persistence location was modified and what executable or command was configured.

False Positive Considerations

Registry Run Keys are also used legitimately by Windows applications, enterprise software, and user-installed applications.

Potential legitimate sources include:

Software installation
Application updates
Enterprise management tools
User-installed applications
Configuration management
Administrative automation

Therefore, a Registry Run Key modification should not automatically be treated as malicious.

Production implementations should consider additional context such as:

User account
Registry value name
Registry value data
Executable path
File reputation
File hash
Digital signature
Parent process
Process creation telemetry
Whether the executable is expected
Whether the modification occurred during software installation or update activity

### Detection Limitations

This lab detection intentionally focuses on Sysmon Event ID 13 and the Windows Registry Run Key location.

The detection identifies:

Registry Value Set
+
CurrentVersion\Run

This provides strong visibility into the persistence mechanism but does not independently prove malicious intent.

A production implementation could be strengthened by correlating the registry modification with additional endpoint telemetry.

For example:

Registry Modification
        +
Process Creation
        +
File Creation

This could help determine whether the newly configured executable was also created or executed around the same time.

Additional correlation with:

Network Connection

could provide further context if the executable was downloaded before the persistence mechanism was established.

### Key Learning

The important lesson from this detection is that persistence can be detected by monitoring the mechanism used to establish it rather than relying only on the executable being persisted.

In this lab, the important behavioral signal was:

Registry Value Set
        +
CurrentVersion\Run

Sysmon Event ID 13 provided visibility into the registry modification, while Microsoft Sentinel provided the detection and alerting layer.

The TargetObject field showed exactly which Run Key was modified, while the Details field showed the value configured for execution.

This provides an effective starting point for detecting Registry Run Key persistence and can be strengthened in production by correlating the registry modification with process, file, user, and network telemetry.
